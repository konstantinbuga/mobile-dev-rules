# QA

**Mission:** nothing reaches `main` that does not work on a fresh install, breaks the contract, or teaches/shows something wrong.

## Every PR

1. Read the task and its acceptance criteria.
2. Automated checks green (`check`, content validator) — on the commit under review.
3. Build debug, **uninstall, install fresh**.
4. Walk the acceptance criteria and neighbouring screens (via the device MCP or adb).
5. Screenshots of affected screens: night/day × 100 %/200 % font × base languages → `qa/screenshots/T-xxx/`.
6. Accessibility on affected screens: accessibility tree, labels, focus order, keyboard (Tab/Enter), screen reader where possible.
7. Verdict in the PR: checklist, links, bugs with severity.

If the branch is behind `main`, test the merged state or say which commit you tested.

## Always (regression)

- No truncated text; longest language at 200 %.
- Readability of every scene element (see `docs/04-acceptance.md`).
- Domain colours unchanged across themes; accent never inside scenes.
- Labels for assumptions present.
- Purchases: buy, restore, pending, offline after purchase.
- Offline: core use works in airplane mode.
- Reproducibility: a reported bug reproduces with its seed.

## Severity

| Level | Meaning | Rule |
|---|---|---|
| S1 | Wrong answer/content, crash, loss of purchase or progress, truncated answer | Blocks merge and release |
| S2 | Feature broken with a workaround; accessibility failure | Blocks release |
| S3 | Visual mismatch, inconvenience | Fix before the milestone |
| S4 | Nit, wish | Backlog |

## Domain correctness

- Truth tables and scenario fixtures are owner-approved; QA checks that tests cover them fully.
- On each release: a manual sample of 20 random tasks by seed, checked against the reference.
- For computed content: independent recalculation of a sample.

## Devices and tooling

- Small emulator (360×640 dp, oldest supported API) for wrapping and performance; a current emulator for the main pass; the owner's phone at milestones (sound, haptics, real performance).
- Emulator recipes (font scale, rotation, TalkBack, coordinates scaling) are in `profiles/<stack>/emulator.md`.
- Ask for debug entry points (deep link to a task by id/seed, clock offset) instead of waiting for rare cases.
- If something can't be checked on the emulator (live screen reader binding, date change without root), say so explicitly in the verdict.

## Release checklist (store submission)

Fresh install on minimum and current API; all modules; purchases with licence testers; offline; accessibility audit; store listing, data-safety form, privacy policy link; content validator `--release` green; crash reporting enabled; version and content version shown in About.
